# 实现计划

状态：首版已实现并通过验收  
更新日期：2026-07-22

## 实施结果

- Python/FastAPI 后端、SQLite/Alembic 数据层和原生 HTML、CSS、JavaScript 管理端已落地。
- 四种协议拥有独立适配器、模型探测、认证注入、健康探测和 usage 归一化。
- 同协议有限故障转移、错误原样返回、请求体临时文件重放和流式响应边界已实现。
- 渠道熔断、15 分钟冷却、后台 `OK` 探测、定时模型发现和日志清理已实现。
- 自动化测试覆盖配置约束、四协议入口、字节一致性、跨协议隔离、熔断恢复和流式统计。
- 使用临时数据库完成真实 OpenAI Compatible 渠道的模型探测和最小 Token 请求验证。
- 管理端已在桌面与移动视口完成浏览器检查，关键页面无页面级横向溢出。
- 默认以 `0.0.0.0:3000` 提供局域网访问且不鉴权；关闭局域网信任后支持手动或随机生成管理/代理密钥。
- usage 观察器支持压缩响应的旁路增量解码，并已使用真实 Brotli 上游响应验证 Token 与缓存统计落库。
- 四种协议均提供面向客户端的模型目录端点，按协议严格隔离并使用原生列表结构返回可路由模型。

## 1. 实施原则

- 先实现可验证的代理核心，再建设统计和管理界面。
- 每个阶段必须包含自动化测试和可运行验收，不把测试集中到最后。
- 透明转发、同协议隔离、有限故障转移和流式边界属于最高优先级回归项。
- 首版保持单进程、SQLite 和本地部署，不提前引入分布式组件。

## 2. 阶段 0：工程骨架与质量基线

### 工作内容

- 创建 `backend` 和 `frontend` 工程。
- 配置 Python 3.12、FastAPI、SQLAlchemy、Alembic、HTTPX 和 pytest。
- 配置原生 HTML、CSS、ES Module JavaScript、History API 与 FastAPI 静态资源回退。
- 建立统一的格式化、静态检查和测试命令。
- 建立后端配置模型，区分启动配置和运行时设置。
- 实现应用启动、关闭、健康检查和前端静态资源托管骨架。

### 验收标准

- 后端能启动并返回系统健康状态。
- 前端静态文件无需构建即可被后端访问，任意管理页历史路径都能回退到入口页。
- 空数据库可通过 Alembic 一次升级到最新版本。
- 后端与前端测试命令在无业务代码时通过。

## 3. 阶段 1：配置、密钥与数据层

### 工作内容

- 实现供应商、渠道、渠道模型、模型路由和候选表。
- 实现健康状态、设置和日志表的首个迁移。
- 启用 SQLite WAL、外键和 busy timeout。
- 实现主密钥生成、文件权限校验、API Key 加解密和统一脱敏。
- 实现 Repository 和事务边界。
- 实现供应商、渠道和设置管理 API。
- 实现模型路由候选整体替换接口和优先级唯一校验。

### 重点测试

- 同一路由写入重复优先级返回 `409`，原列表不变。
- 不同路由可以各自拥有优先级 `0`。
- 跨协议渠道模型无法绑定到路由。
- 不同模型 ID 无法绑定到同一路由。
- API Key 创建后数据库中不存在明文，读取接口不回显密钥。
- 删除存在关联的供应商或渠道被拒绝。

### 验收标准

- 可以通过管理 API 完成供应商、渠道和路由的完整配置。
- 数据库重启后配置、密钥和健康状态仍存在。

## 4. 阶段 2：协议适配器与模型探测

### 工作内容

- 定义 `ProtocolAdapter` 接口和公共 URL/头处理工具。
- 分别实现 OpenAI Compatible、OpenAI Responses、Claude、Gemini 适配器。
- 实现四种协议的模型 ID 提取、流式识别和凭据注入。
- 实现四种格式的模型列表探测、分页和标准化。
- 实现手动模型管理、增量同步与探测任务日志。
- 实现协议专用的网关本地错误外形。

### 重点测试

- Base URL 含或不含尾部 `/` 时都不会产生重复斜杠。
- Base URL 已包含 `/v1` 或 `/v1beta` 时不会重复拼接版本路径。
- 模型提取不会改变原始请求字节。
- 客户端本地密钥不会发送给错误的上游渠道。
- 模型探测按渠道凭据隔离，同供应商不同账号可以得到不同模型列表。
- 探测中消失的自动模型被标记不可见，手动模型不会被删除。

### 验收标准

- 四种渠道均可手动触发模型探测。
- 不支持模型列表的上游可以通过手动添加模型继续配置路由。

## 5. 阶段 3：透明代理与同协议故障转移

### 工作内容

- 实现可重放请求体存储和请求大小限制。
- 实现端到端头复制、逐跳头过滤和上游连接池。
- 实现候选快照、优先级排序和最大尝试限制。
- 实现非流式和流式原始响应转发。
- 实现中间错误响应暂存和最终错误原样返回。
- 实现客户端取消向上游传播。
- 实现网关生成的 `400/404/413/502/503/504`。

### 必测场景

| 场景 | 预期 |
| --- | --- |
| 第一渠道成功 | 不访问后续渠道，响应字节完全一致 |
| 第一渠道 `500`、第二渠道成功 | 客户端只收到第二渠道响应 |
| 第一渠道 `400`、第二渠道成功 | 执行一次切换，`400` 不计熔断 |
| 所有渠道返回 HTTP 错误 | 返回最后一次可用的原始上游错误 |
| 所有渠道连接失败 | 返回网关 `502` |
| 首字节超时 | 未响应客户端时允许切换，最终可返回 `504` |
| 流式输出前断开 | 允许切换 |
| 流式输出后断开 | 终止流，不切换 |
| 客户端取消 | 取消当前上游且不切换 |
| 候选超过最大尝试数 | 只按优先级尝试配置上限 |
| 仅存在其他协议候选 | 返回无路由，不跨协议尝试 |

### 字节级验收

- 使用 mock 上游记录收到的请求体 SHA-256，必须等于客户端发送值。
- 客户端收到的成功和最终错误响应体 SHA-256，必须等于被选定上游返回值。
- SSE 分块内容、顺序和换行保持一致；允许 ASGI/HTTP 层改变网络分块边界，但不得改变字节序列。

### 验收标准

- 四种协议的非流式代理通过集成测试。
- OpenAI、Responses、Claude 和 Gemini 流式代理通过断流边界测试。
- 测试能证明不存在跨协议故障转移。

## 6. 阶段 4：熔断与自动恢复

### 工作内容

- 实现 HTTP 与传输错误分类器。
- 实现并发安全的连续失败计数。
- 实现 `active -> open -> probing` 状态机。
- 实现 15 分钟冷却、启动恢复和探测租约。
- 实现四种协议的最小 `OK` 健康探测请求。
- 实现手动禁用优先级、手动探测和健康重置 API。
- 实现按熔断到期时刻唤醒的一次性健康探测调度和日志。

### 重点测试

- 连续 3 次可计数错误后渠道打开熔断。
- 两次失败之间出现一次成功会清零计数。
- `400/404/422` 不增加失败计数。
- 熔断状态重启后仍保留原截止时间。
- 到期时多个调度协程只能有一个获得探测租约。
- 探测成功静默恢复，失败将截止时间顺延 15 分钟。
- 手动禁用渠道不会被后台探测恢复。
- 健康探测不出现在普通请求统计中。

### 验收标准

- 通过可控时钟测试完整状态转换，无需真实等待 15 分钟。
- 管理 API 和数据库中的健康状态一致。

## 7. 阶段 5：日志与 Token 统计

### 工作内容

- 实现请求日志、尝试日志和有界异步写入队列。
- 实现首字节、首 Token、总耗时、响应字节和 TPS 计算。
- 实现四种协议的流式 usage 观察器和非流式 usage 提取。
- 保存原始 usage 对象并归一化缓存读取、缓存写入、缓存未命中和输出 Token。
- 实现日志筛选、详情、清理和统计聚合 API。
- 实现按保留周期清理日志的后台任务。

### 协议统计映射测试

- OpenAI Compatible 的 `prompt_tokens_details.cached_tokens`。
- OpenAI Responses 的 `input_tokens_details.cached_tokens` 和输出 Token。
- Claude 的 `cache_read_input_tokens`、`cache_creation_input_tokens`、`input_tokens`、`output_tokens`。
- Gemini 的 `usageMetadata` 字段，包括缓存字段不存在时的 `null` 行为。
- 未知或新增字段完整保留在 `raw_usage_json`，不导致解析失败。

### 可靠性测试

- 日志数据库写入失败不影响成功响应。
- 日志队列满时代理仍继续，并增加内部丢弃计数。
- usage 缺失时不估算、不写成零。
- 非流式无法准确识别首 Token 时写 `null`。
- 日志中不存在认证头、密钥、请求正文和响应正文。

### 验收标准

- 可以从一次多渠道故障转移请求追踪每次尝试。
- 统计汇总与固定测试样本人工计算结果一致。
- 所有统计接口均不包含价格数据。

## 8. 阶段 6：原生管理界面

### 页面范围

1. 概览：请求量、成功率、平均首 Token 延迟、TPS、缓存四类 Token、渠道状态。
2. 供应商与渠道：创建供应商、配置账号、更新密钥、探测模型、手动启停。
3. 模型路由：按协议和模型查看候选，使用排序控件调整唯一优先级。
4. 请求日志：筛选列表、请求详情和尝试时间线。
5. 健康状态：熔断倒计时、最近错误、探测记录、手动探测与恢复。
6. 设置：局域网信任、管理/代理密钥、超时、失败阈值、最大尝试数、探测周期和日志保留期。

### 交互要求

- 密钥输入默认隐藏，编辑时不回填现有密钥。
- 优先级通过完整列表保存，冲突时保留用户当前编辑状态并显示服务端错误。
- 渠道状态同时使用图标、文字和颜色。
- 删除供应商、渠道、路由和日志前展示影响范围并二次确认。
- 日志页不会展示提示用户请求正文的入口，因为正文根本不落库。
- 桌面端优先，同时保证常用配置流程在窄屏下无重叠和横向溢出。

### 重点测试

- 供应商到渠道、模型探测、路由排序的完整流程。
- API Key 不会出现在 DOM、浏览器日志或后续 GET 响应中。
- 熔断倒计时结束后能刷新为探测或恢复状态。
- 长模型名、长供应商名和错误文本不会破坏布局。
- Playwright 覆盖桌面和移动视口的关键流程与截图检查。

### 验收标准

- 用户无需编辑配置文件即可完成首个渠道和故障转移路由配置。
- 所有危险操作、加载状态、空状态和失败状态均有完整反馈。

## 9. 阶段 7：整体验收与本地交付

### 工作内容

- 完成原生静态资源与 FastAPI 静态托管，不引入 Node.js 运行时或前端构建步骤。
- 默认启用免鉴权的局域网信任；关闭时支持手动设置或随机生成管理密钥和网关密钥。
- 提供启动、停止、数据库备份和迁移脚本。
- 验证优雅关闭、异常退出恢复和日志保留任务。
- 完成端到端回归、性能基线和安全检查。
- 更新 README，加入安装、运行、配置和故障排查说明。

### 性能基线

在本机 mock 上游条件下记录而不是预设不现实的绝对指标，至少验证：

- 网关首字节附加延迟的 P50/P95。
- 并发流式请求时内存随请求体和连接数的增长是否符合限制。
- 日志开启与关闭时的吞吐差异。
- 大请求落临时文件后不会造成内存同比例增长。
- SQLite 日志清理期间代理延迟无明显尖峰。

### 最终验收清单

- 四种协议均能独立配置、探测模型和发送请求。
- 同协议多渠道严格按唯一优先级故障转移。
- 任意测试都无法触发跨协议请求。
- 请求、成功响应和最终上游错误通过字节一致性校验。
- `400/422` 可切换但不会触发熔断。
- 连续错误、15 分钟冷却、`OK` 探测和静默恢复符合需求。
- 流式响应开始后从不故障转移。
- Token、首 Token 延迟、TPS 和四类缓存字段按协议正确归一化。
- 未知统计保持 `null`，系统不计算价格。
- 密钥不明文落库、不回显、不进入日志。
- 应用监听 `0.0.0.0:3000`，重启后访问策略、配置和熔断状态完整。

## 11. 主要风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 上游兼容接口并不完全兼容 | 协议适配器隔离差异，保留手动模型和集成 fixture |
| 流式统计解析影响代理 | tee 旁路、有界队列、解析失败降级为 null |
| 请求重放占用大量内存 | `SpooledTemporaryFile`、硬大小限制、及时关闭 |
| 并发失败计数不准确 | 数据库原子更新和可控并发测试 |
| 健康任务重复执行 | 单进程约束和探测租约 |
| API Key 泄漏 | 静态加密、响应不回显、统一脱敏测试 |
| SQLite 日志持续增长 | 保留周期、批量清理、容量监控 |
| 中间错误被误发给客户端 | 响应开始标志和故障转移状态机集成测试 |

## 12. 完成定义

一个阶段只有同时满足以下条件才算完成：

- 功能代码、数据库迁移和接口文档一致。
- 该阶段列出的重点测试全部通过。
- 不引入明文密钥、正文日志或价格字段。
- 新增配置有默认值、校验和管理入口。
- 错误路径释放上游连接、临时文件和后台任务资源。
- README 或对应设计文档已同步更新。
