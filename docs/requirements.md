# 需求基线

状态：已确认  
更新日期：2026-07-21

## 1. 目标

构建一个仅供个人本地使用的 AI 网关，将多个供应商账号聚合为统一入口。在不转换协议、不改写业务数据的前提下，根据模型和优先级选择渠道，并在请求尚未向客户端开始响应时执行同协议故障转移。

## 2. 术语与层级

| 名称 | 含义 |
| --- | --- |
| 供应商 Provider | 供应商配置，只保存名称和 Base URL |
| 渠道 Channel | 供应商下的账号，保存 API Key、一个或多个协议类型和启用状态，是路由与熔断的最小单位 |
| 渠道模型 Channel Model | 使用某个渠道凭据从上游探测到的模型及其实际支持协议 |
| 模型路由 Model Route | 管理端按原始模型 ID 合并的逻辑路由；内部仍按协议分池执行 |
| 路由候选 Route Candidate | 逻辑模型路由下的渠道及全局优先级，运行时按渠道协议能力过滤 |

渠道协议是以下四个枚举之一：

- `openai_compatible`
- `openai_responses`
- `claude`
- `gemini`

## 3. 功能需求

### 3.1 配置管理

- 一个供应商只配置名称和 Base URL。
- 一个供应商可以包含多个渠道。
- 每个渠道配置名称、API Key、一个或多个协议类型、是否启用。
- API Key 在管理接口中不可明文回显。
- 支持手动启用和禁用渠道；手动禁用优先于自动恢复。
- 同一模型 ID 只配置一次候选渠道和优先级。
- 同一模型路由内的渠道优先级必须唯一，`0` 为最高；各协议入口仅过滤不支持该协议的渠道，不重新编号。

### 3.2 协议范围

首版代理入口如下：

| 协议 | 代理入口 | 模型探测 |
| --- | --- | --- |
| OpenAI Compatible | `POST /v1/chat/completions`、`POST /v1/completions`、`POST /v1/embeddings` | `GET {base_url}/models` |
| OpenAI Responses | `POST /v1/responses` | `GET {base_url}/models` |
| Claude | `POST /v1/messages` | `GET {base_url}/v1/models`，具体拼接规则由适配器处理 |
| Gemini | `POST /v1beta/models/{model}:generateContent`、`POST /v1beta/models/{model}:streamGenerateContent` | `GET {base_url}/v1beta/models`，具体拼接规则由适配器处理 |

Base URL 视为供应商 API 根地址，不保存末尾 `/v1` 或 `/v1beta`。适配器按请求协议拼接完整版本路径。模型探测失败时允许手动添加模型。

### 3.3 透明转发

- 请求体以原始字节缓存并发送，不反序列化后重新编码。
- 查询参数原样保留，协议所需的上游认证参数除外。
- 上游响应状态码和响应体原样返回。
- 上游最终 HTTP 错误的状态码和响应体原样返回。
- 流式响应事件不合并、不重排、不重新序列化。
- 统计逻辑只能旁路观察数据，不得阻塞或改变转发内容。

代理不可避免的例外：

- 将客户端的本地网关凭据替换为目标渠道的上游 API Key。
- 根据供应商 Base URL 和原始请求路径构造上游地址。
- 删除 `Connection`、`Transfer-Encoding`、`Keep-Alive` 等逐跳头。
- 由 HTTP 客户端重新计算 `Host` 和 `Content-Length`。
- 为 Claude 等协议补充上游强制要求且客户端未提供的认证头。

首版不支持模型别名。客户端请求的模型 ID 必须与候选渠道探测或手动录入的模型 ID 完全一致，因此不需要改写请求体中的 `model` 字段。

### 3.4 路由与故障转移

- 从请求体或 Gemini 路径中只读提取模型 ID；提取失败时直接返回网关生成的 `400`。
- 使用 `(protocol, model_id)` 查找模型路由，绝不进入其他协议的路由池。
- 管理端以模型 ID 合并显示路由；保存时将同一优先级投影到各协议内部路由，只加入实际支持该协议的渠道。
- 仅选择手动启用、自动熔断已关闭且模型绑定启用的候选渠道。
- 候选渠道按优先级升序尝试，每个渠道在一次客户端请求中最多尝试一次。
- 默认最多尝试 3 个渠道，可在全局设置中调整；实际次数不超过候选渠道数量。
- 中间渠道错误只写入尝试日志，不发送给客户端。
- 任一渠道成功后立即停止故障转移。
- 所有候选渠道失败时，返回最后一个收到的上游 HTTP 响应；如果所有失败均发生在建立上游 HTTP 响应之前，则由网关返回 `502` 或 `504`。
- 客户端取消请求后立即取消上游请求，不继续故障转移，也不计为渠道错误。
- 一旦响应头或任意响应体字节已经发给客户端，后续失败不得切换渠道。

### 3.5 错误分类

错误正文不参与路由判断，避免修改或依赖供应商私有错误格式。首版按 HTTP 状态和传输异常分类：

| 类型 | 示例 | 是否切换 | 是否计入连续失败 |
| --- | --- | --- | --- |
| 请求或模型错误 | `400`、`404`、`405`、`413`、`415`、`422` | 是 | 否 |
| 认证或权限错误 | `401`、`403` | 是 | 是 |
| 限流或超时 | `408`、`429` | 是 | 是 |
| 上游服务错误 | `5xx` | 是 | 是 |
| 连接错误 | DNS、连接、TLS、连接超时、首字节超时 | 是 | 是 |
| 客户端取消 | 客户端断开 | 否 | 否 |
| 流式响应中断 | 已向客户端输出后上游断开 | 否 | 是 |

`400/422` 等请求错误不会禁用渠道，但仍会尝试下一个同协议候选渠道，且受最大尝试次数限制。

### 3.6 熔断与恢复

- 默认连续 3 次可计数错误后自动熔断渠道，阈值可配置。
- 成功的普通请求会把该渠道连续失败次数清零。
- 熔断后渠道进入 `open` 状态 15 分钟。
- 到期后调度器只对该渠道执行一次协议专用探测，请求健康检查模型回复 `OK`；正常渠道不进行周期性健康探测。
- 探测成功则静默恢复为 `active` 并清零失败次数。
- 探测失败则重新进入 15 分钟冷却，不参与普通路由。
- 同一渠道同一时间只允许一个探测请求，避免并发恢复。
- 每个渠道可指定健康检查模型；未指定时使用该渠道模型列表中的第一个可用模型。
- 健康检查有独立日志，不计入普通请求统计。
- 应用重启后保留熔断状态和恢复时间。

### 3.7 模型探测

- 模型探测按渠道执行，因为不同 API Key 可能拥有不同模型权限。
- 支持手动触发探测和后台定时探测。
- 探测结果采用增量同步：新增模型自动加入，消失模型标记为不可见，不自动删除已有路由。
- 探测只更新渠道模型目录，不自动改变已有优先级。
- 上游不支持模型列表或返回非标准结果时，允许手动录入模型。

面向客户端的网关模型目录与上游渠道探测相互独立：

- OpenAI Compatible 使用 `GET /v1/models`。
- OpenAI Responses 使用 `GET /v1/responses/models`，或通过 `/v1/models?protocol=openai_responses` 显式选择。
- Claude 使用 `GET /v1/messages/models`，并支持携带 `anthropic-version` 的标准 `/v1/models` 请求。
- Gemini 使用 `GET /v1beta/models`。
- 每个协议目录仅返回已启用且至少有一个可用候选的模型路由。
- `/v1/models` 未显式指定协议时聚合所有协议池，同名模型合并为一条记录。
- 聚合目录保持 OpenAI 标准字段，`data[].x_local_gateway` 仅保留 `supported_endpoints`，列出该模型已配置路由支持的主入口。OpenAI Compatible 只广告 `/v1/chat/completions`，不根据协议类型猜测 Embeddings 能力。
- 通过 `protocol` 查询参数、`X-Local-Gateway-Protocol` 或 `anthropic-version` 选择协议时，仍只返回对应协议的原生结构。
- 返回结构使用对应协议的原生模型列表格式。关闭局域网信任后，模型目录与生成请求使用相同的代理密钥校验规则。
- 模型存在于其他协议池但通过不支持的入口调用时，网关返回 `400 unsupported_model_endpoint`，并给出 `supported_protocols` 与 `supported_endpoints`；此错误在请求上游前产生。

### 3.8 日志与统计

每个客户端请求记录一条请求日志，每次渠道尝试记录一条尝试日志。默认不保存用户请求正文、响应正文和错误正文。

标准统计字段：

| 字段 | 定义 |
| --- | --- |
| 总耗时 | 从接收客户端请求到响应结束或失败 |
| 首字节延迟 | 从开始请求上游到收到第一个响应体字节 |
| 首 Token 延迟 | 流式协议中，从开始请求上游到观察到第一个内容增量；无法识别时为 `null` |
| TPS | 已知输出 Token 数时，`输出 Token / 完整响应耗时`；条件不足时为 `null` |
| 缓存命中 | 上游报告的缓存读取 Token 数 |
| 缓存写入 | 上游报告的缓存创建或写入 Token 数 |
| 缓存未命中 | 归一化后的非缓存输入 Token 数 |
| 输出 | 上游报告的输出 Token 数 |

- 保存上游原始 usage JSON，同时保存归一化字段。
- 上游响应使用 `gzip`、`deflate`、Brotli 或 Zstandard 压缩时，只对旁路统计副本增量解码；发送给客户端的响应头和压缩字节保持原样。
- 上游未提供的字段保存为 `null`，不按 `0` 处理。
- 首版不使用本地 tokenizer 估算缺失 Token。
- 解析或统计失败不得影响响应转发。
- 不保存或计算价格、费用与余额。

## 4. 非功能需求

- 默认监听 `0.0.0.0:3000`，供本机和局域网设备访问。
- “信任局域网访问”默认开启；开启时代理入口和管理接口均不鉴权，客户端不传、传入正确或任意本地 API Key 都不得被拦截。
- 关闭局域网信任后，管理接口和代理入口分别校验独立密钥；密钥可手动设置或由系统随机生成。
- 关闭局域网信任前必须已配置两类密钥，避免管理员界面被意外锁死。
- SQLite 使用 WAL 模式；日志写入采用异步队列，避免阻塞流式转发。
- 首版以单后端进程运行，避免重复执行后台探测任务。
- API Key 加密保存或由权限为 `0600` 的本地密钥保护，日志中始终脱敏。
- 支持配置日志保留天数和定期清理。
- 支持流式与非流式请求。

## 5. 默认运行参数

| 配置 | 默认值 |
| --- | --- |
| 监听地址与端口 | `0.0.0.0:3000` |
| 信任局域网访问 | 开启 |
| 连续失败阈值 | 3 |
| 熔断时间 | 900 秒 |
| 最大故障转移尝试 | 3 |
| 连接超时 | 10 秒 |
| 首字节超时 | 60 秒 |
| 首 Token 超时 | 60 秒 |
| 流式空闲超时 | 300 秒 |
| 非流式总超时 | 600 秒 |
| 模型自动探测周期 | 24 小时 |
| 日志保留时间 | 30 天 |

所有默认值均可通过管理界面修改，但修改不影响已经开始的请求。

## 6. 首版不包含

- 跨协议转换或跨协议故障转移。
- 模型别名及请求体模型字段改写。
- 加权负载均衡、随机路由或并发竞速请求。
- 请求结果缓存或语义缓存。
- 价格、成本、配额余额统计。
- 多用户、角色权限和公网部署能力。
- 请求与响应正文审计。
