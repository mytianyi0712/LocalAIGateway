# 自定义模型 + 可配置模型列表可用性筛选

## 目标

1. **支持自定义模型**：在「模型路由」页可以自己填写一个网关侧模型 ID（自由文本），然后选择「渠道 + 该渠道上的模型」作为请求源。
2. **一个自定义模型支持多个 ID 不同的请求源**：候选可以来自不同渠道、不同 `model_id`（例如 A 渠道的 `gpt-4o`、B 渠道的 `claude-sonnet`）。客户端请求 `my-gpt`，网关按现有优先级策略选候选，并**用该候选自己渠道上的 `model_id`** 转发到对应渠道。
3. **可配置模型列表只显示有供应渠道的模型**：上游已不返回（`available=0`）、渠道被删除 / 手动禁用 / 熔断中，都视为「没有供应渠道」，不再出现在「添加路由」下拉中（数据库保留该模型）。
4. **绝不静默删除已配置的模型**：渠道删除只减少该路由的候选，`model_routes` 行保留并继续显示在路由列表中，直到用户手动删除。

## 现状与关键约束

- 路由标识 = `model_routes.requested_model_id`，每个协议一行（`UNIQUE(protocol, requested_model_id)`）。
- **运行期不校验 ID 相等**：`resolve_candidates`（`infrastructure.rs:129-150`）按 `mr.requested_model_id = ?` 关联候选并 select `cm.model_id`，从不比较两者。`Candidate.model_id` 也**从未被消费** —— 所有候选今天都发送同一个 `model` 字符串。
- **唯一阻塞在管理端写路径**：`admin/routes.rs:213` `if upstream != model || !available` 拒绝 ID 不一致的候选；`create_route:126` 只从 `model_id == requested_model_id` 的渠道模型推导协议。
- **没有 schema 约束**：`route_candidates` 只有 `(route_id, channel_model_id)` / `(route_id, priority)` 唯一约束（`migrations/0001_gateway_schema.sql:110-111`）。→ **本方案不需要数据库迁移。**
- 请求体在「同协议且无映射」时是**逐字节透传**（`proxy.rs:2245-2247`）；gemini 的模型在 **URL 路径**里（`protocol.rs:357-365`，`mapped_path` `proxy.rs:235-242/255-262`）。
- 渠道删除：`delete_channel`（`admin/channels.rs:394-406`）先删该渠道模型的 `route_candidates`，再删渠道（`channel_models` 级联），**`model_routes` 不动** → 孤儿路由已符合目标 4。
- 发现任务对消失的模型置 `available=0`，不删除（`discovery.rs:889-930`）；无任何后台任务删除路由/候选。
- 文档现状：`requirements.md:69`「首版不支持模型别名……不需要改写请求体中的 `model` 字段」、`api-design.md:418`「原始模型 ID 与 `requested_model_id` 一致」、`data-model.md:13/171` —— 均需随本特性更新。

## 设计决策（已与用户确认）

- 请求源 = 已有的 `channel_models` 行；上游 `model_id` 直接复用该行的 `model_id`，**不新增覆盖字段**。
- 自定义模型 ID 为自由文本；协议由创建时勾选（也支持从已探测模型自动带出）。
- 「没有供应渠道」= `available=0` **或** 渠道 `manual_enabled=0` **或** `channel_health.state != 'active'` **或** 渠道已删除。
- 筛选范围：仅「模型路由」页的**添加路由下拉**（映射页预设/已配置模型下拉不在本次范围）。
- 孤儿路由保留、可见，需用户手动删除。

## 非目标

- 不新增数据库迁移、不新增候选覆盖字段（复用 `channel_models.model_id`）。
- 不自动删除任何 `model_routes` / `model_caps` / 映射。
- 不改映射页预设下拉与「上游模型」下拉的筛选（用户只要求添加路由下拉）。
- 不改发现任务、健康探测、余额、Command Code 登录等旁路逻辑。

## 风险与权衡

- 自定义模型请求会重新序列化 JSON（`serde_json` 无 `preserve_order`，顶层键顺序会变）；仅在 `candidate.model_id != 请求模型` 时发生，普通配置仍逐字节透传。上游按 JSON 解析，提示缓存以消息内容为键，影响可接受。
- 直连非映射请求的上游响应 `model` 会回显真实上游 ID（与今天非自定义路由行为一致，接受）。
- 放宽候选校验后，同协议下候选下拉会列出所有可用模型（列表变长），UI 需分组/显示上游 ID 以便区分。
